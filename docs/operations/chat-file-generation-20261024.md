# 普通聊天生成文件

用户复现：`帮我生成一个出师表的 txt`，只收到正文和“当前无法直接附加 TXT 文件”。

原因：`write_file` 仅在绑定工作区后注册；会话产物工具缺少普通文本文件生成入口；完成判定只识别 Office/图表请求，未把 TXT/Markdown 等纳入文件交付检查。前一轮的预览链接改动仅改善已存在文件的展示。

修复：

- `generate_file` 无需工作区，生成并持久化会话作品；支持 TXT、Markdown、CSV、JSON、HTML、源代码等文本格式，返回真实 artifactId、版本和下载地址。Office 和其他二进制格式继续使用专用工具，不用文本改扩展名冒充。
- 提示要求调用工具交付；文件请求只贴正文时继续执行，失败的生成结果不算已交付。
- 成功工具事件加载并选中对应作品，按所属会话打开作品面板；聊天中保留蓝色文件卡片和下载按钮。历史卡片可重新打开。
- 文本预览原样显示换行、符号和 HTML 文本，不解释 Markdown；UTF-8 下载支持中文文件名和指定版本。

验证：先用用户原句复现 4 项失败，修复后相关 7 个测试文件 46 项通过；另有纯文本预览回归检查。TypeScript 检查、主进程构建、API 冒烟测试通过。页面用真实生成工具与隔离会话存储生成示例节选，验证了文件卡片、右侧预览、卡片重新打开、下载实际落盘。

本机测试使用 `NODE_OPTIONS=--no-experimental-webstorage`，避免 Node 25 的实验性全局 localStorage 干扰 jsdom。更新了两个原有测试的环境/展示假设：打字机测试同时模拟 Date，命令卡按实际 JSON 参数验证原命令。

运行中的 Reizo 需要重新启动以加载工具、提示和下载接口，然后重新提交或重试原请求；旧的纯文本回复不会自动产生文件。

隔离页面：`http://127.0.0.1:46174/.cache/file-output-qa.html`。该页用于组件/工具交互验收，不调用线上模型；示例文件为《出师表》节选。

会话作品面板宽度（2026-10-24）：按用户截图默认设为 320px，使用独立的 `reizo:artifact-panel-width` 保存用户拖动后的宽度。旧画布/编辑器的宽度继续使用原存储键，避免会话作品继承宽面板或最大化状态而挤压聊天。保留拖动、展开和收起。宽度切换、关闭重开及重新加载的回归测试通过。

重复回复修复：实际会话 trace 记录一次 `generate_file` 成功后仍出现两次 `undelivered` 续写。原交付标志只更新工具旁路 `emit`，SDK 工具结果走标准会话事件流，没有更新该标志。改为续写判定直接读取 canonical turn snapshot 中的成功工具结果。真实 runtime + SDK 事件 + 内存 SQLite/作品存储回归测试中，修复前 provider 调用 3 次，修复后 1 次且作品仍只有 1 份。失败、未完成及无效文件结果不算交付。

界面保留文件卡片下载；Markdown AST 展示层仅移除与成功卡片同 ID、同版本的本地下载链接，并合并简单的重复完成句。历史原文和文件不改写；注意事项、其他作品/版本、外部链接和代码示例保留。Streamdown 的处理器缓存以插件名称及参数建键，因此文件 ID/版本通过插件参数传递，避免消息间错误复用处理规则。新回复提示明确只确认一次，不另外输出下载链接。
