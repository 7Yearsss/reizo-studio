# 视频链接分析

## 使用与范围

在普通对话中贴一个视频链接，或要求分析链接中的视频，调用 `analyze_video`。
单独发送已识别的视频直链或 X、YouTube、抖音、哔哩哔哩等站点链接时，运行时要求第一步调用该工具；技能、专家和计划模式的工具限制仍然生效。

工具使用 Electron 自带 Chromium，在 Windows 和 macOS 运行同一实现，不依赖视频剪辑面板、外部 FFmpeg 或 Python。
支持浏览器能实际解码的有限时长视频，包括可访问的网页播放器、MSE/blob 流播放器和 MP4/WebM 直链。站点名称不是可访问性的保证；登录墙、验证码、DRM、直播、跨域 iframe 及站点反自动化限制可能阻止读取。
需要登录时用 `browser_open`，用户自行在客户端浏览器登录，然后以 `signedIn:true` 重试；不读取系统 Chrome/Safari 的登录信息，也不让用户在聊天里发送密码。

## 证据与结果

- 默认按时长采样，最多 16 帧，覆盖开头和结尾；可指定 `startSeconds`、`endSeconds`、`frameCount`（2–24）复查局部。
- 返回真实解码画面和实际时间戳，不把帖子配文、封面或评论当作视频内容。
- 读取可用的 HTML 字幕轨道。没有自动转写完整音轨；无字幕时根据画面分析，并明确标注声音未转写。
- 画面是抽样证据，不能据此声称观看了连续全过程、听到了声音，或验证了视频真实性。
- 采样中不播放扬声器声音，不申请麦克风、摄像头或系统录屏权限。
- 对话显示分析卡片、来源、时长、帧数及字幕/音频状态；文字分析仍由当前支持视觉输入的对话模型生成。已知纯文本模型会直接提示切换。

## 数据与权限

默认浏览器分区临时使用并清理；登录模式只复用 `persist:reizo-browser`。
窗口没有桌面 preload，开启沙箱、上下文隔离和网页安全；禁止弹窗、下载及权限请求。
导航和媒体子请求校验公网地址及 DNS，拒绝本机、私网、元数据地址、凭据 URL；DNS 校验不等于连接 IP 固定，仍存在校验后地址变化的边界。

在“每次询问”模式中，审批前不打开视频；卡片说明关键帧和字幕会发送给当前对话模型。
计划模式、只读自动化、技能和专家白名单不能被自动分析覆盖。页面和字幕文字均标为不可信数据。

帧存于 `<dataRoot>/video-analysis/<uuid>/frame-NN.jpg`，记录仅保存 ID、元数据及文件名。
恢复模型上下文时只从本会话合法 ID 的固定文件名重建图片内容；最近一次分析可重用，旧结果按上下文预算压缩。文件缺失会明确指出，不会重新提交或拿其它画面冒充。
每帧不超过 512 KiB、一次最多 6 MiB、同一进程最多两个读取窗口，整体读取上限 3 分钟；取消、失败或超时销毁读取窗口。

## 验证

- 采样、字幕去重、取消清理、错误帧拒绝和公网请求检查的单元测试。
- 实际运行时测试覆盖裸链接优先调用、审批继续、跨回合图片恢复及只读模式限制。
- 流播放器先发 `seeked`、后提供解码数据时继续等待；必要时短暂静音播放以加载所需片段。Chat Completions 的工具图片转为独立图片消息，避免 SDK 将图片编码当 JSON 文本交给模型；保留整批工具结果的顺序和时间戳。
- `npm run check:video-analysis` 在本机 Electron 内实际解码 MDN 的 CC0 测试视频，核验起中末画面、时间点、不同图像和非空彩色像素。
- Windows/macOS 发包任务均运行原生解码检查；这不等于每个平台都已做登录网站的人工验收。
