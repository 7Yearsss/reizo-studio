# Windows packaging verification

Forge Vite builds the main/preload and renderer into `.vite/build` and `.vite/renderer`. The app archive includes only these runtime directories; private QA files elsewhere under `.vite` are excluded. `pptxgenjs`, `image-size` and `jszip` are explicit production dependencies and Vite bundles their JavaScript into the main chunk. SQLite migrations are embedded TypeScript strings, so the package does not depend on external SQL files.

Bundled `skills/` is copied to `resources/skills`, including each `SKILL.md`, `contract.json` and image asset. Packaged startup adds this directory before `dataRoot/skills`, so user skills retain their final override priority. The Forge plugin's default `.vite`-only copy policy would otherwise omit all bundled skills.

`node scripts/package-compatibility.mjs` creates a fresh `reizo-package-qa-*` directory under the system temporary directory, packages Windows x64 and writes a receipt. It never starts the packaged Electron application. Forge uses shared `.vite` intermediate directories, so coordinate this command with other Vite builds and performance measurements; a separate output directory alone does not isolate compilation.

`scripts/package-module-smoke.cjs <temporary-package-root>` reads the actual ASAR, confirms private QA files are absent and extracts it into a new fixture directory. The smoke test discovers minified main-bundle bindings from unique stable literals and exposes them only in its in-memory module wrapper. Original ASAR and extracted bundle bytes remain unchanged. Electron startup is stubbed; no windows, real `userData`, providers or charges are involved. Run it with the supported Node runtime. Its receipt distinguishes module execution from launching the packaged Electron executable.

The smoke checks bundled contracts against the final source byte-for-byte, applies embedded migrations to a new fixture database, and exports a real PNG/JPEG PPTX with an empty `PATH`. It also checks native download bytes and UTF-8 `Content-Disposition`: the artifact title becomes a safe `.pptx` filename, with separators/control characters removed and an ASCII fallback. Other MIME download behavior is unchanged.

FFmpeg/ffprobe are **not bundled** in this package. PNG/JPEG/GIF PPTX export works without them; WebP conversion and video composition require an explicitly configured compatible executable or binaries supplied in the app `resources` directory. `REIZO_FFMPEG_PATH` and `REIZO_FFPROBE_PATH` override the respective executables, with `resources/ffmpeg.exe` / `resources/ffprobe.exe` and then host `PATH` as fallbacks. A missing executable produces an explicit installation/configuration error and a failed job, rather than a simulated successful output. The smoke's WebP case checks this failure under empty `PATH`. No workstation GPL FFmpeg binary is copied into the release; selecting and documenting a redistributable binary remains release work.

This check does not establish PowerPoint/Keynote/Google Slides behavior, packaged Electron UI startup, installer signing, non-NTFS compatibility or sudden power-loss durability. Those need their own checks; module smoke success must not be described as testing them.
