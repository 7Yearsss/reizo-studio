# Reizo 借鉴 NewMax 的交互对照与改造方案

日期：2026-10-16。状态：方案，未实施。

建议保留 Reizo 的左侧导航、中央 Agent 对话、右侧创作工具，以及单一标题栏和现有黑白灰视觉体系。优先借鉴 NewMax 的功能入口、会话导航、任务提示和产物打开方式。第一阶段不改模型调用、Turn 生命周期、存储格式和账号体系。

## 对照依据

- NewMax：本机 `E:\NewMax` 的 1.1.5 安装包，已观察主界面、已有对话、输入区、任务摘要及工作区相关入口；界面中的更新提示不代表已安装版本。其他页面尚未逐项完成操作验证。
- NewMax 静态分析：主进程和 preload 的组合分析匹配出 134 条 IPC 关系。主进程存在混淆和分析调用栈限制；这些结果可以辅助定位功能，不能证明运行时行为。
- Reizo：当前工作区的组件、状态与类型契约。项目约定见 [CONTEXT.md](../CONTEXT.md)。README 中的能力描述以实际挂载关系为准。
- 本轮仅整理方案。账号登录相关未提交改动属于既有工作，不纳入改造范围。

## 建议的目标布局

```text
┌────────────────────── 唯一标题栏 ─────────────────────────────┐
│ Logo / 侧栏 / 返回    [会话 A] [会话 B] [+]    搜索 / 面板 / 窗口 │
├───────────────┬────────────────────────┬─────────────────────┤
│ 开始创作      │ 当前工作区提示          │ 画布 / 文档 / 文件   │
│ 搜索          │                        │                     │
│ 技能          │ 对话内容               │ 对应的现有编辑器     │
│ 我的作品      │ 可按提问定位           │ 或文件预览           │
│ 自动化        │                        │                     │
│               │ 产物卡 → 在右侧定位 ──→│                     │
│ 项目          │                        │                     │
│ 最近对话      │ 当前任务名称 · 2/5      │                     │
│ 今天 / 更早   │ 输入、附件、模型和权限  │                     │

```

右面板关闭时对话占满剩余空间；打开时保持可拖动、最大化和关闭行为。当前工作区提示应属于轻量上下文，不挤占为第二个标题栏。窄窗口减少文字和并排入口，优先保证输入与消息可用。

## 第一阶段 高频入口与进度提示

目标：只使用现有能力，让新用户更容易开始、查找、切换和理解当前任务。

### 搜索与新建

左侧加入明确的搜索入口，调用现有 `openGlobalCommandPalette`。搜索范围继续覆盖会话、技能、文件和操作，不另建一套搜索弹窗。新建操作复用 `newLauncherTab`，维持“已有空白入口时复用”的行为。

验收：鼠标入口和 Ctrl/⌘K 打开同一个搜索面板；从搜索结果进入现有会话不重复建会话；关闭弹窗回到原位置；是否新增 Ctrl/⌘N 需要同时核对 Electron 菜单和输入法快捷键。

### 任务摘要

将 `ComposerDock` 的纯数字提示增强为“当前进行中的任务 · 完成数/总数”。无进行中任务时展示下一项待办；全部完成时明确显示已完成。点击仍打开现有完整计划。

验收：长标题省略但可查看全文；多个进行中任务有明确选取规则；无任务不占位；窄窗口、提问卡和消息队列同时出现时不覆盖可读内容；Esc 与点击外部可关闭。

### 高频面板入口

宽窗口优先提供“画布”和“文件”的直接入口，其他工具保留在现有菜单。复用 `TopRightToolbar` 的会话创建及面板打开逻辑，避免入口间产生不同状态。

验收：相同入口重复点击的打开/关闭语义一致；首页打开需要会话的工具时沿用现有创建逻辑；当前面板有清晰选中态；缩窄后仍能在菜单中找到全部工具。

## 第二阶段 会话切换与长对话

### 将会话标签接入现有标题栏

`TabBar` 已有切换、关闭、关闭其他标签和新增入口；`MainLayout` 已保留非活动会话的挂载。可将标签接入标题栏中央区域，协调 `ChatPage` 当前标题/重命名 portal，避免标题和标签重复占位。全局功能页与会话页要明确区分：打开设置不应悄悄关闭正在运行的会话。

验收：切换标签保留草稿、滚动位置和运行状态；关闭标签不删除会话或隐式停止 Turn；关闭当前标签有稳定回退；多标签溢出可滚动；Windows 拖窗区域及按钮可点击区域不冲突；键盘焦点可见。

### 会话时间分组

优先在现有最近会话中展示“今天、昨天、更早”等分组，保留运行中、待回答和未读标记。搜索时仍按可理解的规则呈现结果；项目归属与工作区筛选不随视觉分组改变。

归档不能用删除模拟。当前 `SessionSummary`、`SessionPatch` 没有归档字段，需单独扩展存储、API、恢复入口和搜索规则，安排在后续阶段。

### 对话段落导航

以用户提交的提问为目录项，使用稳定消息 ID 定位。打开目录不改变当前对话；点击某条提问后定位到对应消息；新回复不能把正在阅读历史的位置拉回底部。

验收：较早消息尚未挂载时，先扩展窗口化渲染范围再滚动；同样文本的多条消息仍可区分；编辑/重试后的目录顺序正确；流式追加不抖动；与现有搜索及“回到底部”入口协调。

## 第三阶段 产物与工作区上下文

### 统一产物打开反馈

继续使用现有 Office 卡片和图片/视频缩略图，统一名称、类型、位置与打开反馈。图片点击定位现有画布节点；文档、表格和演示稿打开对应工件。选中态应识别具体产物，不能只判断右面板的类型。

“本轮产物”需要将产物绑定到实际 Turn、工具结果或已验证的来源。历史消息缺少归属信息时标为会话级产物，不把整个工作区文件宣称为本轮生成。缺失文件或资源已删除时保留解释和可恢复入口。

### 显示正确的工作区

当前会话的 `workspacePath` 与设置中的默认工作区是两个不同来源。聊天中显示会话自己的工作区；首页展示新会话将采用的默认目录。实施前核对文件树、Git、终端和文件引用究竟读取哪个来源，统一作用范围。

暂不直接照搬多工作区标签。多工作区涉及会话筛选、文件根目录、终端实例、权限及持久化，必须先明确切换时哪些内容一起切换。

## 实施边界与验证

第一批建议包含搜索入口、任务摘要、高频面板入口。第二批再处理标题栏标签、时间分组和段落导航；最后统一产物与工作区作用范围。这样每一批都能单独体验，容易判断是否真的减少操作。

保留 Reizo 的画布、视频剪辑和 Office 工作区能力，保持 `CONTEXT.md` 中 Turn、Continuation、Interruption、Resume 和 Retry 的语义。菜单切换或视觉上的“完成”不能改变真实执行状态。第一阶段也不把 NewMax 的浏览器、长期计划、每日回顾视为现成后端能力。

实施时验证普通对话、流式回复、待回答、待批准、队列、中断、切换会话、关闭标签及重启恢复。界面验证覆盖浅色/深色、宽/窄窗口、键盘操作、长标题和较长历史；测试优先针对跨组件状态行为，而非仅断言 CSS 类名。

NewMax 的新建、搜索、段落跳转、文件面板切换和窗口缩放仍需完成逐项操作观察。第一批实施前补齐这些证据，用于确定具体行为，不据静态 IPC 名称推断用户流程。
